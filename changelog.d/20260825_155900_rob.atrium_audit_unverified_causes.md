### Fixed

- **A clean summary now says what it examined, and what it could not.** `doctor`
  printed "nothing looks wrong across 3 nodes" on a graph with no git and no
  journal, where the age, volatility, correction and drift checks had had
  nothing to run against. Every one of them returned empty because it could not
  run, and the headline read as agreement. `check` said "no problems" about a
  file it had read and a history it had never opened; `trust` said "nothing to
  challenge - every declaration has history and none is stale", which named two
  of its six checks and claimed the other four by silence (#41).

  All four - `check`, `review`, `trust`, `doctor` - now name their own scope on
  a clean run, and list what could not be checked separately from what was
  checked and found nothing. `docs/BOUNDARY.md` already required this of a
  corroborator, from a report where "zero conflicts across 26 rows" hid a
  missing edge behind a true number (#88). The kernel was not exempt and is now
  held to it too.

  `doctor`'s second line used to guess: "either a good graph or a graph too
  small to disagree with - probably the second". That is a plausible cause
  offered as a finding, which is the thing this issue is about, and it was
  standing in for an answer the tool already had.

- **An absence we could not read is no longer reported as an absence.**
  `trellis history` said "no history yet" for a graph with no journal, a graph
  whose journal is empty, and a graph whose journal exists and cannot be
  parsed - the last of which is history that *was* recorded. `snapshot --list`
  said "no snapshots yet" for an unreadable index, and for snapshots sitting on
  disk that no index names. Both now distinguish the cases, and both count the
  lines they skipped rather than dropping them in silence (#41).

- **Four more messages named a cause the code had not established** (#41).
  `explain <node> --gate finish` said "nothing gates this node" when what it
  had found was that `finish` is not declared. It now names the gates that are,
  and - since only the gate you asked about is evaluated - says which of them
  are unmet rather than implying they are met. `review`'s `[x] explain` said
  the same thing whether a node had no gate or a satisfied one, which are
  opposite answers. `reconcile` said "this graph has no gates yet" on finding
  no edges, and a gate whose expression names no other node is a gate without
  an edge. `blocking --all` said "nothing is holding anything up" without
  saying it had looked at open work only.
