### Changed

- **A changelog entry is now a new file in `changelog.d/`, not a new line in
  `CHANGELOG.md`.** Every pull request that added an entry conflicted with
  every other one that did, because they all appended to the same list; nothing
  else about them conflicted. Four merged in one day and one of them was
  rebased twice over a file whose resolution was the same mechanical move each
  time (#81).

  The cost was never the merge. It was that clearing it rewrites a published
  branch and re-runs CI, and each pass is a chance to drop a paragraph while
  resolving prose nobody diffs closely - in the one file whose whole job is to
  be read before upgrading.

  It also scaled the wrong way: any two open pull requests collided by
  construction, so the tax grew with work in flight. `scriv collect` folds the
  fragments into `CHANGELOG.md` under one version heading when a release is
  cut, grouped by the `### Added` headings the fragments already carry.

  A `.gitattributes` line setting `merge=union` on `CHANGELOG.md` would have
  made the symptom disappear in one line and was refused. Union merge resolves
  silently by interleaving, and an entry that reads as coherent prose while
  describing two changes as one is precisely the failure this file exists to
  not have. Here a loud conflict beats a quiet corruption.
